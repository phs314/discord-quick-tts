# 디스코드 서버별 봇 자리(BotSeat)를 speech 의 애그리거트로 둔다

"먼저 온 채널 우선"(ADR 0007) 규칙이 세 곳에 흩어져 있었습니다. 거절 판단은 `SpeakQuickChatService`, "봇만 남은 채널은 쓰이지 않는다" 판단은 `JdaVoiceChannelLocator`, 같은 판단이 자동 퇴장용 `EmptyVoiceChannelWatcher` 에 한 번 더 있었고, 상태는 JDA 캐시에만 있었습니다. 그래서 세 가지 문제가 있었습니다.

- 모든 디스코드 서버의 요청이 `synchronized (this)` 잠금 하나를 지나갔습니다. 서로 상관없는 디스코드 서버끼리 기다립니다.
- 봇이 막 들어가는 1초쯤은 JDA 가 아직 연결된 채널을 모르니, 그 사이 다른 채널에서 온 문장이 봇을 옮길 수 있었습니다.
- `SpeechPlayerPort.play` 가 "시키면 그 채널로 옮겨 가서 읽는다" 여서 연결을 옮기는 결정이 어댑터 안에 숨어 있었습니다.

## 결정

- `speech/domain/BotSeat` 를 만듭니다. 디스코드 서버 하나에서 봇이 앉은 음성 채널을 기억하고, 식별자는 `GuildId` 입니다. "이 채널에서 읽으러 가도 되나"(`isFreeFor`, `sitIn`), "이제 나가야 하나"(`vacateIfEmpty`), "관리자가 봇을 옮기거나 끊었다"(`followBotMove`) 를 이 객체가 판단합니다.
- 봇 서버가 들어가기로 정한 순간 자리를 잡습니다. 디스코드 연결이 끝났는지는 보지 않으므로 1초 틈이 없어집니다. 채널에 사람이 있는지는 매번 `VoiceChannelLocatorPort.hasPeople` 로 디스코드에 물어 넘겨줍니다. 사람 수까지 자리에 담으면 디스코드 이벤트를 모두 따라가야 해서 그러지 않았습니다.
- 잠금은 디스코드 서버마다 따로입니다. `BotSeatPort.withSeat(guildId, work)` 가 그 디스코드 서버의 자리를 잠그고 꺼내 주며, 메모리 저장소(`InMemoryBotSeatRepository`)는 자리 객체 자체를 잠금으로 씁니다. 봇 서버가 다시 켜지면 봇도 음성 채널에서 나가 있으므로 자리를 DB 에 둘 필요는 없습니다.
- `SpeechPlayerPort` 를 `join` / `play` / `leave` 로 나눕니다. 어느 채널로 갈지와 언제 나갈지는 애플리케이션이 정하고, 어댑터는 시키는 대로만 합니다.
- 자동 퇴장도 유스케이스로 옮깁니다(보고서 G2). 인바운드 어댑터 `VoiceStateListener` 가 디스코드 음성 상태 소식을 받아, 사람이 나갔으면 `LeaveEmptyVoiceChannelUseCase`, 봇 자신이 옮겨지거나 끊겼으면 `FollowBotMoveUseCase` 를 부릅니다.

## 고르지 않은 것

- 서비스에 디스코드 서버별 잠금만 넣기: 작은 변경이지만 1초 틈과 흩어진 규칙은 그대로입니다.
- 어댑터가 "들어가는 중인 채널" 도 기억하기 (ADR 0007 이 남겨 둔 방법): 틈은 막지만 규칙이 어댑터에 더 숨습니다.
- 자리에 사람 수까지 담기: 디스코드 음성 이벤트를 놓치면 자리가 실제와 어긋납니다. 사람 수는 JDA 캐시가 이미 잘 알고 있습니다.

## 결과

- 같은 디스코드 서버에서는 자리 잡기, 채널 들어가기, 재생 순서 넣기가 한 번에 하나씩 일어납니다. 그 안에서 임시 음성 파일도 쓰지만 같은 디스코드 서버의 요청만 기다립니다. 음성 생성(TTS)은 잠금 밖에서 합니다.
- 채널에 들어가지 못하면(권한 없음 등) 예외가 나고 자리는 바뀌지 않습니다. 다만 디스코드 연결이 나중에 실패하면 자리는 남아 있습니다. 그 채널에서 다시 보내면 다시 들어가고, 사람이 다 나가면 자리가 빕니다.
- 관리자가 봇을 끌어 옮기면 자리도 따라가고, 연결을 끊으면 자리를 비우고 남은 문장을 버립니다. 자리가 이미 다른 채널이면(봇 서버가 옮기는 중에 늦게 온 소식) 무시합니다.
- 서비스는 9개가 됐습니다(`LeaveEmptyVoiceChannelService`, `FollowBotMoveService` 추가, ADR 0008).
- `BotSeat` 는 처음으로 상태가 바뀌는 애그리거트입니다. 식별자(`guildId`)만 `final` 이고 앉은 채널은 메서드로만 바뀝니다 (ADR 0003 의 "필드는 `private final`" 의 예외).
- "봇 여러 개" 방식(ADR 0007)을 검토하게 되면 이 객체가 "어느 봇이 어느 채널에 있나" 를 맡게 됩니다.
