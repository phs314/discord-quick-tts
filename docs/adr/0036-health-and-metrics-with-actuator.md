# 상태 확인과 지표는 Actuator 로 보고, 디스코드 연결과 TTS 를 거기에 더한다

- 상태: 일부 대체됨
  - 디스코드 연결 `UP` 기준을 JDA 하나에서 모든 샤드로 → ADR 0046
- 날짜: 2026-10-18

서버가 살아 있는지, 디스코드에 붙어 있는지, TTS 가 얼마나 실패하는지 볼 방법이 없었습니다. Edge 목소리는 비공식 API 라 언제든 막힐 수 있는데(ADR 0006), 막혔는지는 사용자가 "구글 목소리로 나와요" 라고 말해 줘야 알았습니다. 데스크톱 클라이언트는 서버가 떠 있는지 보려고 `GET /` 를 불러 아무 응답(401)이나 오면 떠 있다고 봤습니다. 이 ADR 은 ADR 0031 의 "기기 등록만 토큰 없이 연다" 에 상태 확인 하나를 더합니다.

## 결정

1. **스프링 부트 Actuator 를 씁니다.** 웹으로는 `health` 와 `metrics` 만 엽니다.
   - `GET /actuator/health` 는 토큰 없이 열고, 세부 내용 없이 `UP`/`DOWN` 만 보여 줍니다. 하나라도 `DOWN` 이면 503 입니다.
   - `/actuator/metrics` 는 다른 API 처럼 기기 토큰이 있어야 봅니다.
2. **디스코드 연결은 `config/DiscordHealthIndicator` 가 봅니다.** JDA 가 게이트웨이에 붙어 있을 때(`CONNECTED`)만 `UP` 입니다. JDA 빈이 `config` 에 있으므로 같은 곳에 둡니다.
3. **TTS 지표는 TTS 어댑터 안에서 셉니다.** `MultiEngineSpeechSynthesizer` 가 Micrometer 로 두 가지를 셉니다.
   - `quicktts.tts.synthesis`: 목소리(`voice`)와 결과(`outcome`: success, failure)별로 걸린 시간과 횟수
   - `quicktts.tts.fallback`: 고른 목소리(`voice`)로 못 읽어 Google 번역 목소리로 대신 읽은 횟수

   포트, 서비스, 도메인은 지표를 모릅니다.
4. **클라이언트는 상태 확인 주소로 서버가 떠 있는지 봅니다.** 경로는 `QuickTtsApi.HEALTH_PATH` 에 두고, 지금처럼 무슨 응답이든 오면 떠 있다고 봅니다. 디스코드 연결이 잠깐 끊겨 503 이 와도 서버를 하나 더 켜지 않기 위해서입니다.

## 결과

- 막혔는지는 `/actuator/metrics/quicktts.tts.fallback` 이 늘어나는 것으로, 느려졌는지는 `quicktts.tts.synthesis` 로 압니다.
- 상태 확인은 디스코드 연결과 함께 스프링 부트가 기본으로 넣는 DB, 디스크 공간도 봅니다.
- 의존이 하나 늘고, 보안 설정에 토큰 없이 여는 줄이 하나 늘었습니다.
- 지표를 그래프로 볼 화면(Prometheus, Grafana)은 아직 없습니다. 배포할 때 따로 정합니다.

## 고르지 않은 것

- 상태 확인을 직접 만든 컨트롤러(`GET /api/v1/ping` 같은)로 하기: 디스코드, DB 상태를 합치는 일을 다시 만들게 되고 스프링에서 흔한 방식이 아닙니다.
- 지표를 토큰 없이 열기: 개인용이라 숨길 것은 적지만, 누가 얼마나 쓰는지가 드러나므로 다른 API 처럼 막아 둡니다.
- 지표를 서비스나 도메인에서 세기: 지표는 기술 관심사라 헥사고날 경계 밖인 어댑터에 둡니다.
