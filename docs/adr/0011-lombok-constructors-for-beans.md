# 필드 주입만 하는 스프링 빈은 모두 @RequiredArgsConstructor 를 쓴다

ADR 0009 에서 서비스 7개에 Lombok `@RequiredArgsConstructor` 를 쓰기로 했지만, 컨트롤러, 디스코드 리스너, 저장소 같은 다른 빈 11개는 필드를 대입만 하는 생성자를 계속 손으로 썼습니다. 같은 일을 두 방식으로 하다 보니 새 빈을 만들 때마다 어느 쪽으로 쓸지 정해야 했습니다.

Lombok 은 ADR 0009 로 이미 빌드에 들어와 있어서, 범위를 넓혀도 새 위험(새 JDK 를 늦게 따라가는 문제)은 생기지 않습니다.

## 결과

- 생성자가 `final` 필드를 대입하기만 하는 스프링 빈(서비스, 컨트롤러, 리스너, 어댑터, 설정)은 `@RequiredArgsConstructor` 를 붙이고 생성자를 직접 쓰지 않습니다.
- 생성자에서 다른 일도 하는 빈은 지금처럼 직접 씁니다. 지금은 `LavaPlayerSpeechPlayer`(오디오 소스 등록)와 `EdgeReadAloudEngine`(설정에서 값 꺼내기) 두 개입니다.
- 테스트는 지금처럼 `new` 로 만듭니다. Lombok 이 만든 생성자는 필드를 적은 순서대로 인자를 받으므로, 필드 순서를 바꾸면 생성자 인자 순서도 바뀝니다.
- getter 등 다른 Lombok 기능, 값 객체(record)와 애그리거트(ADR 0003)에는 여전히 쓰지 않습니다.
