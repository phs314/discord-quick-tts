# 연결 코드도 DB 에 두고, 기기 테이블의 기본 키는 기기 ID 로 한다

- 상태: 채택
- 날짜: 2026-11-01

`/연결` 로 발급한 연결 코드(`Pairing`)는 봇 서버 메모리(`PairingMemoryAdapter`, `ConcurrentHashMap`)에만 있었습니다. 기기(`device` 테이블)는 기본 키가 토큰 해시(`token_hash`)였고, 기기 ID(`id`)는 유일 인덱스만 있었습니다. 둘 다 서버가 한 프로세스일 때만 괜찮은 모양입니다.

- 봇 서버를 다시 켜면 발급한 코드가 모두 사라집니다. 사용자는 `/연결` 을 다시 해야 하고, 왜 코드가 안 되는지 알 수 없습니다.
- 디스코드 봇과 웹 API 를 다른 프로세스로 나누거나 서버를 두 대 띄우면, 코드를 발급한 프로세스와 받는 프로세스가 달라서 연결이 안 됩니다. 처음부터 커질 것을 생각해 두기로 했으므로, 나눌 때 다시 고치지 않게 지금 옮깁니다.
- 기기 등록은 `@Transactional` 인데 코드를 꺼내는 일은 메모리라서, 기기 저장이 실패해도 꺼낸 코드는 되돌아오지 않았습니다.
- 토큰 해시는 기기를 가리키는 값이 아니라 기기의 비밀번호에 가깝습니다. 토큰을 다시 발급하면 바뀌는 값이 기본 키이면 그 줄을 다른 줄로 바꿔야 하고, 다른 테이블이 기기를 가리킬 때도 바뀌는 값을 따라가야 합니다. 실무에서 흔한 모양은 바뀌지 않는 ID 가 기본 키, 토큰 해시는 유일 인덱스입니다.

## 결정

1. **`pairing` 테이블을 만들고 `PairingPersistenceAdapter` 가 `PairingPort` 를 구현합니다** (Flyway `V4`). 열은 `code`(기본 키), `discord_user_id`, `expires_at` 입니다. 메모리 어댑터와 `identity/adapter/out/memory` 폴더는 지웁니다.
2. **꺼내기는 읽은 뒤 지우고, 지운 줄이 1 일 때만 돌려줍니다.** 두 요청이 같은 코드를 동시에 써도 한쪽만 기기를 등록합니다. 메모리 때 `ConcurrentHashMap.remove` 가 맡던 일을 `delete` 의 지운 줄 수가 맡습니다(ADR 0028 의 6번).
3. **만료된 코드는 새 코드를 저장할 때 함께 지웁니다.** 따로 정해진 시간마다 도는 작업을 두지 않습니다. 만료된 코드를 꺼내는 일은 지금처럼 도메인(`Pairing.redeem`)이 막습니다.
4. **코드 발급(`IssuePairingCodeService`)에도 `@Transactional` 을 붙입니다.** 이제 DB 에 쓰므로 ADR 0033 의 규칙에 들어옵니다. 기기 등록은 코드 지우기와 기기 넣기가 한 트랜잭션이라, 기기 저장이 실패하면 코드도 되살아납니다.
5. **`device` 테이블의 기본 키를 `id` 로 바꾸고 `token_hash` 는 유일 인덱스로 둡니다** (Flyway `V5`). 엔티티의 `@Id` 도 `id` 입니다. 이미 있는 기기 줄은 그대로 남습니다.
6. 도메인 `Pairing` 에는 저장소에서 되살릴 때 쓰는 `restore` 와 `expiresAt()` 을 더합니다.

## 결과

- 봇 서버를 다시 켜도 5분 안에 발급한 연결 코드를 쓸 수 있습니다. 봇과 API 를 다른 프로세스로 나눠도 코드가 이어집니다.
- 저장소 테스트(`PairingPersistenceAdapterTest`)는 다른 저장소처럼 H2 와 MySQL 양쪽에서 돕니다. 옛 DB 를 이어 쓰는 테스트는 V4, V5 를 지난 뒤 기기를 토큰 해시와 ID 로 찾고 새 기기와 연결 코드를 넣어 봅니다.
- 코드를 발급할 때마다 만료된 줄을 지우는 `delete` 가 한 번 더 돕니다. `expires_at` 에 인덱스가 있어 줄이 많지 않으면 비용이 거의 없습니다.

## 고르지 않은 것

- Redis 같은 따로 띄우는 저장소: 5분짜리 코드 몇 개 때문에 배포할 것이 하나 늘어납니다. 이미 있는 DB 로 충분합니다.
- `@Scheduled` 로 만료된 코드 지우기: 서버를 여러 대 띄우면 모두가 같은 작업을 돌립니다. 저장할 때 지우면 따로 생각할 것이 없습니다.
- `select ... for update` 로 잠그고 꺼내기: 지운 줄 수로 충분히 한 번만 꺼내지고, H2 와 MySQL 의 잠금 차이를 신경 쓰지 않아도 됩니다.
