# Release 노트는 PR 제목의 타입으로 나눈다

- 상태: 채택
- 날짜: 2026-10-14

Release 본문의 PR 목록은 GitHub 자동 생성(`--generate-notes`, [ADR 0020](0020-github-releases-and-update-notice.md))이라, 그 사이 머지된 PR 이 머지 순서대로 한 줄씩 나옵니다. 리팩터링, 테스트, CI 정리처럼 쓰는 사람에게는 달라지는 게 없는 PR 이 새 기능 사이에 섞여서, 이번 버전에서 무엇이 바뀌었는지 한눈에 보이지 않습니다.

## 결정

- PR 제목은 이미 커밋 컨벤션처럼 `<이모지> [<타입>] <요약>` 모양입니다. **PR 라벨** 워크플로가 PR 이 열리거나 제목이 바뀔 때 Release Drafter 의 Autolabeler 로 `[타입]` 과 같은 이름의 라벨(`feat`, `fix`, `refactor` ...)을 답니다. 타입마다 제목을 맞춰 볼 정규식은 `.github/release-drafter.yml` 에 있고, 타입 목록은 커밋 메시지 검사(`scripts/check-commit-msg.sh`)와 같습니다. 제목을 고쳐 타입이 바뀌면 예전 타입 라벨은 뗍니다(`sync-labels`).
- Release Drafter 는 라벨을 다는 데만 씁니다. 초안 Release 는 만들지 않고, Release 는 지금처럼 태그 푸시로 만듭니다.
- `.github/release.yml` 이 자동 생성 노트를 라벨로 나눕니다. `feat` 는 **✨ 새 기능**, `fix` 는 **🐛 버그 수정**, 나머지 타입과 라벨 없는 PR 은 맨 아래 **🔧 기타** 로 갑니다.
- 리팩터링·테스트·문서도 노트에서 빼지 않고 "기타"에 둡니다. 무엇이 들어갔는지는 다 남기되, 쓰는 사람이 볼 것만 위로 올립니다.
- 버전은 쓰는 사람에게 보이는 변화가 있을 때 올립니다. 리팩터링만 쌓였을 때는 태그를 찍지 않고, 다음 기능이나 버그 수정과 함께 냅니다.

## 고르지 않은 것

- 라벨을 손으로 달기: 잊기 쉽고, 제목에 이미 타입이 있어 두 번 적는 셈입니다.
- 리팩터링·테스트·문서를 노트에서 빼기: 버전 사이에 무엇이 바뀌었는지 Release 에서 다 볼 수 없게 됩니다. 노트가 너무 길어지면 그때 뺍니다.
- Release Drafter 로 노트까지 만들기: 초안 Release 를 따로 관리해야 하고, 태그 푸시로 Release 를 만드는 지금 흐름과 겹칩니다. 노트는 GitHub 자동 생성 노트의 묶음 기능으로 충분해서 Autolabeler 만 씁니다.
- 라벨 다는 스크립트를 워크플로에 직접 쓰기: 처음에는 이렇게 했지만, 제목 파싱과 라벨 추가·제거를 손으로 관리해야 합니다. 널리 쓰는 액션의 설정 파일 하나로 같은 일을 합니다.
- 제목을 Conventional Commits(`feat: ...`) 로 바꾸기: 라벨 도구 대부분이 이 모양을 기대하지만, 이미 쌓인 커밋·PR 과 커밋 메시지 검사가 지금 형식을 쓰고 있어 바꾸지 않습니다. Autolabeler 는 정규식으로 지금 형식을 그대로 읽습니다.

## 결과

- 라벨은 노트를 만드는 순간 기준으로 읽힙니다. 이미 올라간 Release 는 다시 만들어지지 않으므로, v0.1.0 과 v0.2.0 은 지난 PR 에 라벨을 단 뒤 나눈 노트를 Release 편집 화면에 직접 붙여 넣었습니다.
- PR 제목이 컨벤션과 다르거나 모르는 타입이면 라벨이 붙지 않고 "기타"로 갑니다. 그때는 제목을 고치면 라벨이 다시 붙습니다.
- 워크플로는 `pull_request_target` 으로 돌고 PR 의 코드를 받아 오지 않습니다. 권한은 저장소 읽기와 PR 쓰기만 줍니다. 워크플로와 `.github/release-drafter.yml` 은 기본 브랜치의 것을 쓰므로, 규칙을 바꾸는 PR 은 머지된 뒤부터 적용됩니다.
- 아직 없는 타입 라벨은 GitHub 가 라벨을 붙일 때 기본 회색으로 만듭니다. 색과 설명은 라벨 화면에서 고칩니다.
- PR 제목에 `@Service` 같은 어노테이션을 쓰면 노트에서 GitHub 사용자 멘션이 되므로 백틱으로 감쌉니다.
