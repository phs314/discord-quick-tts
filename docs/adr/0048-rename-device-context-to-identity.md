# device 컨텍스트를 identity 로 부른다

- 상태: 채택
- 날짜: 2026-11-01

`device` 컨텍스트는 `/연결` 코드 발급, 기기 등록, 기기 토큰 인증, 연결 해제를 맡습니다. 하는 일은 "이 요청을 보낸 사람이 어느 디스코드 사용자인가" 를 알아내는 것이고, 기기는 그 수단입니다. 그런데 컨텍스트 이름이 안의 애그리거트 이름(`Device`)과 같아서, 컨텍스트를 말하는지 기기 하나를 말하는지 글에서 매번 가려야 했습니다. 웹 화면 로그인이나 디스코드 OAuth 처럼 사람을 알아내는 다른 방법이 생기면 `device` 라는 이름이 더 맞지 않게 됩니다. 이 ADR 은 ADR 0002 의 컨텍스트 이름 하나를 바꿉니다.

## 결정

1. **패키지 `quicktts.bot.device` 를 `quicktts.bot.identity` 로 바꿉니다.** 누가 보낸 요청인지 알아내는 일을 실무에서 흔히 identity(신원) 로 부르는 것을 따릅니다(ADR 0044 의 2순위).
2. **안의 이름은 그대로 둡니다.** `Device`, `Pairing`, `PairingCode`, `DeviceToken`, `/연결`, `/연결해제`, 웹 경로(`/api/v1/devices`), 오류 코드(`invalid-device-token`), `device` 테이블은 바뀌지 않습니다. 기기는 디스코드 설정 화면의 "기기" 와 같은 뜻이라 맞는 이름입니다(ADR 0044).
3. `ArchitectureTest` 의 컨텍스트 지도와 헥사고날 규칙도 `identity` 로 부릅니다. 다른 컨텍스트와 서로 모르는 것은 그대로입니다.

## 결과

- 동작, 웹 API, DB 는 바뀌지 않습니다. 패키지와 문서의 컨텍스트 이름만 바뀝니다.
- 사람을 알아내는 새 방법(웹 로그인 같은)이 생기면 이 컨텍스트에 더하고, 다른 컨텍스트는 지금처럼 shared 의 `DiscordUserId` 만 받습니다.

## 고르지 않은 것

- `auth` / `authentication`: 인증 한 가지만 뜻해서, 기기 등록과 연결 해제처럼 신원을 만들고 지우는 일이 이름에서 빠집니다.
- `account`: 디스코드 계정과 헷갈리고, 우리는 따로 계정을 두지 않습니다(사람은 디스코드 사용자 ID 로만 가리킴).
- `device` 그대로 두기: 컨텍스트와 애그리거트 이름이 계속 겹칩니다.
