# 문장은 speech 도메인에서 읽기 좋게 다듬은 뒤 엔진에 보낸다

- 상태: 채택
- 날짜: 2026-10-11

지금까지는 보낸 문장을 그대로 TTS 엔진에 넘겼습니다. 그래서 ㅋㅋ 는 자모 이름으로, 이모지는 이름으로, 링크는 글자 하나씩 읽힐 수 있었습니다. 채팅하듯 치는 문장에는 이런 글이 자주 섞여서, 읽기 전에 다듬기로 했습니다.

## 결정

- 다듬는 규칙은 speech 컨텍스트의 도메인에 둡니다. `QuickChatMessage.toSpokenText()` 가 규칙을 적용해 새 값 객체 `SpokenText`(읽을 문장)를 만들고, `SpeechSynthesizerPort.synthesize` 는 `QuickChatMessage` 대신 `SpokenText` 를 받습니다. 엔진은 다듬어진 글만 봅니다.
- 규칙은 현수가 정한 네 가지뿐입니다.
  - 링크(`http://`, `https://`, `www.` 로 시작하는 글)는 "링크를 보냈어요" 로 읽습니다.
  - 이모지는 지웁니다. 피부색, 이음 문자로 묶은 가족 이모지, 국기, ❤️ 같은 변형 선택자도 함께 지웁니다. 숫자, `#`, `*` 는 남깁니다.
  - 따로 쓴 자음 ㅋ·ㅎ·ㅇ·ㄴ·ㄱ 는 키·히·이응·니은·고 로 읽습니다. 반복은 줄이지 않고 반복된 만큼 읽습니다 (ㅋㅋㅋ → 키키키).
  - 그 밖의 글자(ㅠㅠ, 다른 자음, 문장부호 반복)는 그대로 둡니다.
- 다듬고 나서 읽을 내용이 없으면(이모지만 보냄) `InvalidDomainValueException("읽을 내용이 없습니다.")` 로 400 `invalid-value` 를 돌려줍니다. 서비스는 채널을 찾기 전에 다듬으므로 봇은 채널에 들어가지 않고, 클라이언트는 지금처럼 그 문구를 트레이 알림으로 보여 줍니다.
- 200자 제한은 보낸 문장 그대로 셉니다. 입력창의 글자 수 표시와 맞추기 위해서입니다.

## 고르지 않은 것

- TTS 어댑터(`MultiEngineSpeechSynthesizer`) 안에서 다듬기: 포트는 그대로라 변경이 작지만, "무엇을 읽어 주나" 는 엔진과 상관없는 서비스 규칙입니다. 엔진을 바꾸거나 더할 때 규칙이 따라 옮겨야 하고, 빈 문장 안내도 어댑터 예외로 해야 해서 어색합니다.
- 데스크톱 클라이언트에서 보내기 전에 다듬기: 옛 exe 나 다른 클라이언트는 다듬지 않은 문장을 보냅니다.
- 규칙을 별도 도메인 서비스 클래스로 빼기: 규칙이 네 가지라 `QuickChatMessage` 안의 메서드로 충분합니다. 사용자별 발음 사전처럼 저장된 데이터가 필요해지면 그때 뺍니다.

## 결과

- 새 규칙은 `QuickChatMessage.toSpokenText()` 에 더하고 `QuickChatMessageTest` 에 예시를 더합니다.
- ㅠㅠ, 초성 줄임말 사전, 반복 줄이기는 보류했습니다.
