# ADR 에 상태와 날짜를 붙이고, 바뀐 결정은 새 ADR 로 쓴다

- 상태: 채택
- 날짜: 2026-10-18

ADR 0001~0033 에는 상태도 날짜도 없었습니다. 결정이 바뀌면 옛 ADR 본문을 바로 고쳐서 바뀐 줄에 `~~취소선~~` 을 긋고 "ADR 00xx 로 바뀌었습니다" 를 덧붙였습니다. 그래서 세 가지가 불편했습니다.

- ADR 을 열었을 때 이 결정이 지금도 맞는지 알 수 없습니다. 본문을 끝까지 읽고 취소선을 찾아야 합니다. 0009 처럼 세 번 고친 ADR 은 무엇이 남았는지 따라가기 어렵습니다.
- 결정 하나를 바꾸는 PR 이 옛 ADR 여러 개의 본문을 함께 고칩니다. 동시에 열린 PR 끼리 같은 문단을 고쳐 부딪힙니다.
- ADR 이 30개가 넘었는데 모아 보는 목록이 없어서, 어느 주제가 어디 있는지 파일 이름으로 찾아야 했습니다.

## 결정

1. **모든 ADR 의 제목 아래에 `- 상태:` 와 `- 날짜:` 두 줄을 둡니다.** 상태는 `채택`, `일부 대체됨`, `대체됨` 셋 중 하나이고, `일부 대체됨` 과 `대체됨` 은 상태 줄 아래에 바뀐 것을 한 줄씩(`  - 무엇이 어떻게 → ADR 00xx`) 적습니다. 상태 줄만 읽어도 본문의 어디가 지금과 다른지 알 수 있게 하려는 것입니다. 날짜는 그 파일이 저장소에 처음 들어온 날이고, `git log --diff-filter=A --follow` 로 누구나 같은 값을 얻습니다.
2. **채택된 ADR 의 본문은 고치지 않습니다.** 결정이 바뀌면 새 ADR 을 쓰고, 옛 ADR 은 상태 줄만 바꿉니다. 오타나 깨진 링크처럼 뜻이 바뀌지 않는 고침만 본문에 합니다.
3. **0001~0033 에 남은 취소선과 "바뀌었습니다" 는 지우지 않습니다.** 결정이 어떻게 바뀌어 왔는지 보여 주는 기록입니다. 그 흔적을 보고 상태를 정했습니다. 본문 일부가 뒤의 ADR 로 바뀐 것은 `일부 대체됨`, 나머지는 `채택` 입니다. 전체가 바뀐 ADR 은 아직 없습니다.
4. **`docs/adr/README.md` 에 쓰는 법과 주제별 목록(링크, 상태)을 둡니다.** 새 ADR 을 더하거나 상태를 바꾸면 목록도 같은 PR 에서 고칩니다.

## 결과

- 0001~0033 중 20개가 `일부 대체됨`, 13개가 `채택` 입니다. 뒤의 ADR 이 이름·자리 규칙을 빌드 검사에서 리뷰로 돌린 것(ADR 0032)처럼 지키는 방법만 바뀐 것도 `일부 대체됨` 으로 적었습니다. 상태 줄과 날짜 줄 말고는 본문이 바뀌지 않았습니다.
- 0001~0017 의 날짜는 저장소 첫 커밋 날(2026-10-11)입니다. 그보다 먼저 정한 결정도 있지만(본문의 2026-10-09 등), 정확한 날을 알 수 없어 저장소에 들어온 날로 맞춥니다.
- 지금 규칙을 한눈에 보는 곳은 여전히 저장소 README 의 "봇 서버 구조" 와 `ArchitectureTest` 입니다. 결정이 바뀌면 이 둘은 새 결정에 맞게 고칩니다.
- 번호 0031~0033 은 이 결정과 함께 열려 있던 다른 PR 이 썼습니다. 그 ADR 들에도 같은 상태 줄과 날짜 줄, 목록 줄을 더했습니다.

## 고르지 않은 것

- 옛 ADR 본문을 지금 결정에 맞게 다시 쓰기: 읽기는 쉬워지지만, 왜 그때 그렇게 정했고 무엇 때문에 바꿨는지가 사라집니다.
- 지금처럼 본문을 바로 고치기: 새 파일이 없어 간단하지만, 지금 맞는 결정을 찾으려면 본문을 다 읽어야 하고 열린 PR 끼리 같은 ADR 을 고쳐 부딪힙니다.
- 상태를 목록에만 두기: ADR 파일만 연 사람은 그 결정이 바뀌었는지 모릅니다.
- 상태 줄에 바꾼 ADR 번호만 적기: 짧지만, 본문의 어디가 바뀌었는지 보려면 새 ADR 을 열어 봐야 합니다.
- `제안됨`, `폐기됨` 같은 상태도 두기: 이 저장소에서는 ADR 이 PR 과 함께 머지될 때 들어와서, 제안과 폐기는 PR 이 맡습니다.
- 날짜로 결정한 날을 찾아 적기: 첫 커밋 전의 결정은 날을 알 수 없고, 사람마다 다른 날을 고를 수 있습니다.
