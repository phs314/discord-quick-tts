# 설치 파일은 GitHub Releases 로 나눠 주고, 새 버전은 트레이 알림으로 알린다

지금까지 설치 파일은 **설치 파일** 워크플로의 Actions 아티팩트로만 받을 수 있었습니다. GitHub 에 로그인해야 받을 수 있고, 14일이 지나면 사라지며, 버전도 늘 0.1.0 이었습니다. 이미 설치한 사람은 새 버전이 나왔는지 알 길도 없었습니다. 남들도 쓰게 하려면 로그인 없이 받을 수 있는 고정된 다운로드 페이지와, 새 버전을 알려 주는 방법이 필요합니다.

## 결정

- `v1.2.3` 모양의 태그를 푸시하면 **설치 파일** 워크플로가 그 버전으로 `QuickTTS-1.2.3.exe` 와 `QuickTTS-1.2.3-windows.zip` 을 만들고, 태그 이름으로 GitHub Release 를 만들어 두 파일을 올립니다. 본문에는 설치 안내와, 지난 Release 이후 머지된 PR 목록(GitHub 자동 생성)이 들어갑니다. → [ADR 0022](0022-release-notes-by-pr-type.md) 에서 PR 종류별로 나눴습니다.
- 버전은 태그에서만 정합니다. 워크플로가 `-PappVersion=1.2.3` 으로 넘기고, 태그가 아닌 빌드(PR, main, 개발 PC)는 기본값 0.1.0 을 씁니다. 버전을 올리려고 코드를 고치는 커밋은 만들지 않습니다.
- exe 를 만들 때 `-Dquicktts.version=버전` 을 넣고, QuickTTS 는 켜질 때 GitHub API 의 최신 Release(`/releases/latest`, 초안과 미리 보기 제외)를 한 번 확인합니다. 태그 버전이 더 높으면 트레이 알림을 띄우고, 알림이나 트레이 메뉴의 **Download v버전...** 을 누르면 Release 페이지를 브라우저로 엽니다.
- 내려받기와 설치는 사용자가 합니다. 설치 파일은 업그레이드 UUID 가 같아서, 실행하면 이전 설치를 지우고 그 자리에 깔립니다 ([ADR 0018](0018-windows-installer.md)).
- 확인에 실패하면(오프라인, GitHub 응답 이상) 아무것도 알리지 않습니다. Gradle 로 바로 띄운 개발 중에는 버전을 모르므로 확인하지 않습니다.

## 고르지 않은 것

- 자동 업데이트(내려받아 바로 설치): 서명하지 않은 설치 파일을 몰래 받아 실행하는 셈이고, 실행 중인 QuickTTS 와 봇 서버를 끄고 다시 켜는 처리가 필요합니다. 쓰는 사람이 늘고 코드 서명을 하게 되면 다시 봅니다.
- 봇 서버에 최신 버전 API 를 두기: 서버마다 버전 정보를 따로 관리해야 하고, 지금은 PC 마다 자기 봇 서버를 띄우는 경우가 많습니다. 설치 파일이 있는 GitHub 를 바로 보는 편이 단순합니다.
- 버전을 `build.gradle.kts` 에 적고 태그와 맞는지 검사하기: 릴리스마다 버전 커밋이 하나씩 생기고, 둘이 어긋나는 실수를 막는 검사를 따로 둬야 합니다.
- 켜져 있는 동안 주기적으로 확인하기: Start with Windows 로 켜 두면 하루 한 번쯤은 다시 켜집니다. 필요해지면 하루 간격 확인을 더합니다.

## 결과

- Release 를 만드는 건 태그 푸시 하나입니다. `git tag v0.2.0 && git push origin v0.2.0`. 태그가 `v숫자.숫자.숫자` 모양이 아니면 워크플로가 실패하고 Release 를 만들지 않습니다.
- 저장소가 공개라서 Release 의 설치 파일은 누구나 로그인 없이 받을 수 있습니다.
- 버전 확인을 넣기 전에 만든 exe(0.1.0)는 알림을 띄우지 않습니다. 첫 Release 는 직접 받아서 설치해야 하고, 그다음부터 알림이 뜹니다.
- 태그가 아닌 빌드는 늘 0.1.0 이라, 그런 빌드를 쓰는 PC 에는 Release 가 있는 동안 알림이 뜹니다. 개발 중에 Actions 아티팩트로 받은 설치 파일은 Release 보다 버전이 낮아서 Release 버전 위에는 설치되지 않을 수 있습니다. 그때는 QuickTTS 를 제거하고 설치합니다.
- GitHub API 는 로그인하지 않으면 IP 마다 한 시간에 60번까지 부를 수 있습니다. 켜질 때 한 번이라 충분합니다.
